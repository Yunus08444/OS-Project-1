# Практическая работа №1 — Вариант B

## 1. Цель работы

Изучить управление пользователями и группами Linux, права доступа к каталогам, команды `su` и `sudo`, а также настройку оболочки Bash.

## 2. Создание пользователя и группы

Группа `developers` уже существовала в системе. Пользователь `student2` также существовал, поэтому для него был обновлён пароль и выполнено добавление в группу.

Команда:

```bash
sudo usermod -aG developers student2
```

Результат проверки:

```text
uid=1002(student2) gid=1002(student2) groups=1002(student2),100(users),1001(developers)
```

## 3. Настройка каталога /srv/shared

Каталог создан с владельцем `root` и группой `developers`.

Выполненные команды:

```bash
sudo mkdir -p /srv/shared
sudo chown root:developers /srv/shared
sudo chmod 2775 /srv/shared
ls -ld /srv/shared
```

Результат:

```text
drwxrwsr-x 2 root developers ... /srv/shared
```

Права `2775` позволяют владельцу и участникам группы читать, записывать и входить в каталог. Остальные пользователи могут читать содержимое каталога и входить в него, но не могут создавать или удалять файлы.

Бит setgid обеспечивает наследование группы каталога новыми файлами и подкаталогами.

## 4. Проверка создания и удаления файлов

Файл создан от имени `student2`:

```bash
sudo -u student2 bash -c 'echo "Created by student2" > /srv/shared/student2.txt'
```

Содержимое проверено командой `cat`.

Основной пользователь `tuf-yunus` не входит в группу `developers`. Поэтому он не имеет права записи в каталог и не может удалять файлы из него без дополнительных привилегий.

После включения setgid новые файлы получили группу `developers`, что подтверждено командой `ls -l`.

## 5. Разница между su и sudo

`su` позволяет переключиться на другого пользователя, например:

```bash
su - student2
```

Команда `whoami` после переключения выводит `student2`.

`sudo` позволяет выполнять отдельные команды с правами другого пользователя, обычно `root`, если это разрешено настройками системы.

Проверка:

```bash
sudo whoami
```

Результат:

```text
root
```

В Ubuntu прямой вход под root обычно отключён по умолчанию, поскольку пароль root не установлен. Для административных операций используется `sudo`.

## 6. Настройка ~/.bashrc

В файл `~/.bashrc` добавлены два alias и переменная окружения:

```bash
alias ll='ls -la'
alias croot='cd /'
export COURSE_NAME="OS-PR1"
```

Проверка:

```bash
source ~/.bashrc
ll
croot
pwd
echo $COURSE_NAME
```

Результаты:
- `ll` выводит подробный список файлов.
- `croot` переводит в корневой каталог `/`.
- `COURSE_NAME` содержит значение `OS-PR1`.

Настройки проверены также в новой сессии Bash.

## 7. Вывод

В ходе практической работы изучены управление пользователями и группами, настройка прав доступа к каталогам, наследование группы с помощью setgid, переключение пользователей через `su`, выполнение административных команд через `sudo` и настройка Bash.
